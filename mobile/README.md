# Resonator mobile bindings (M11 groundwork)

uniffi bindings over `crates/ffi` (`resonator-ffi`): the mobile-appropriate
core of a resonator node. No extism mods host and no web server are
compiled in (`rsntr` is consumed with `default-features = false`); the
pure-Rust SPARQL engine and bundled sqlite mean no C loadable extensions
are needed, per the design constraint recorded in PLAN.md sec 8.

## Layout

- `swift/`, `kotlin/`: generated uniffi bindings, checked in
  (regenerated by the build scripts; unformatted, since swiftformat and
  ktlint are not required tooling).
- `build-ios.sh`: release staticlibs for `aarch64-apple-ios` and
  `aarch64-apple-ios-sim`, regenerated Swift bindings, and
  `dist/ResonatorFFI.xcframework` (requires Xcode).
- `build-android.sh`: `libresonator_ffi.so` for `aarch64-linux-android`
  plus regenerated Kotlin bindings (requires an Android NDK; the script
  refuses clearly when none is found).
- `ios/`: Swift package (`Package.swift` binds the xcframework, the
  generated bindings compile as its source) plus
  `Example/ResonatorDemoView.swift`, a SwiftUI example to copy into an
  app.
- `android/`: gradle application module skeleton
  (`build.gradle.kts`, `settings.gradle.kts`, one `MainActivity` that
  creates a node, writes a row, and shows vibrations).
- `dist/`: build output (xcframework); not checked in.

## API surface (same shape in Swift and Kotlin)

- `Node(dir, offline)`: creates or reopens a node directory (sqlite db +
  ed25519 key). Every method is blocking; call off the main thread.
- `serve()` / `stop()` / `isServing()`: serving runs on the crate's own
  background tokio runtime.
- `ticket(waitMs)`, `addPeer(name, ticketOrId)`, `endpointId()`.
- `localQuery` / `localExecute` (owner channel, ungated, audited),
  `sparql` (SELECT/ASK rows, CONSTRUCT as `turtle`), `queryPeer`.
- `chatInit`, `chatSend`, `chatLog`.
- `entrain(point, listener) -> Entrainment`: the `VibrationListener`
  callback fires `onVibration` per signal of the Sympathetic point and
  `onEnd` when the entrainment stops; `Entrainment.damp()` ends it.
  While not serving, entrainments and local writes share one in-process
  pipeline (a local write vibrates); while serving, calls route to the
  serving pipeline so remote writes vibrate too. Entrainments opened
  before `serve()` stay on the standalone pipeline: damp and re-entrain
  after starting to serve.
- Do not call `Node` methods from inside `onVibration`/`onEnd`.

## Verified on this machine (macOS 15, Xcode 26.5, rustc 1.97.1)

- `cargo test -p resonator-ffi`: host-side test over a temp dir (init,
  local execute/query, sparql update+select+construct, chat send/log,
  vibration callback from a table write, damp, unknown-point refusal).
- `cargo check -p resonator-ffi --target aarch64-apple-ios` and
  `--target aarch64-apple-ios-sim`: clean.
- `./mobile/build-ios.sh`: built `dist/ResonatorFFI.xcframework`
  (device + simulator slices).
- The `mobile/ios` Swift package compiled for the iOS simulator
  (`xcodebuild -scheme Resonator -destination
  'generic/platform=iOS Simulator' build`): generated bindings link
  against the xcframework cleanly.
- Binding generation for Swift and Kotlin (library mode, from the host
  cdylib).

## Scaffolded only (toolchain absent here)

- `aarch64-linux-android`: the rust target is installed, but no Android
  NDK is present (`$ANDROID_NDK_HOME` unset, no `~/Library/Android/sdk/ndk`),
  so cross-compilation stops at `cc`/linker discovery. `build-android.sh`
  encodes the full recipe and guards on the NDK.
- The gradle module and `MainActivity` are written against the checked-in
  generated Kotlin (API names verified against
  `kotlin/uniffi/resonator_ffi/resonator_ffi.kt`)
  but are not compile-checked: without the NDK there is no `jniLibs/`
  payload, and AGP/dependency downloads were not exercised.

## Build: iOS

    ./mobile/build-ios.sh

Produces `mobile/dist/ResonatorFFI.xcframework` and copies the generated
bindings into `mobile/ios/Sources/Resonator/`. Then depend on the local
package `mobile/ios` from an app project and copy
`mobile/ios/Example/ResonatorDemoView.swift` in as a starting point.
The package targets iOS 15+ (the xcframework carries device and
simulator slices only).

## Build: Android

1. Install an NDK (Android Studio: SDK Manager -> SDK Tools -> "NDK
   (Side by side)"), or set `ANDROID_NDK_HOME`.
2. `./mobile/build-android.sh` (override the api level with
   `ANDROID_API`, default 24). This drops
   `mobile/android/src/main/jniLibs/arm64-v8a/libresonator_ffi.so` and
   refreshes `mobile/kotlin/`.
3. `cd mobile/android && gradle assembleDebug`.

The Kotlin bindings load the native library via JNA (`jna:5.14.0@aar`),
already declared in `build.gradle.kts`.

## Regenerating bindings by hand

    cargo build -p resonator-ffi
    cargo run -p resonator-ffi --features bindgen --bin uniffi-bindgen -- \
        generate --library target/debug/libresonator_ffi.dylib \
        --language swift --out-dir mobile/swift
    # same with --language kotlin --out-dir mobile/kotlin

uniffi is pinned in the workspace `Cargo.toml` (`0.28`); bindings and
library must always be generated from the same build.
